
# Day 0 – 100 Days of DevOps: Roadmap & Learning Journey

## 1. Introduction

This repository documents my journey through the **100 Days of DevOps** learning roadmap.

The goal is to develop practical knowledge of DevOps tools, Linux administration, automation, containerization, orchestration, CI/CD and cloud infrastructure.

Rather than focusing only on theoretical concepts, I will work on practical tasks, understand the commands being used, troubleshoot errors and document my learning every day.

Each day's notes will include the objective, concepts, practical steps, commands, verification and key takeaways.

## 2. Learning Objectives

By completing this 100-day roadmap, I aim to:

- Understand Linux administration and server configuration.
- Learn Git and version control workflows.
- Build and manage Docker containers and images.
- Understand Kubernetes and application orchestration.
- Create CI/CD pipelines using Jenkins.
- Automate server configuration using Ansible.
- Provision cloud infrastructure using Terraform.
- Understand AWS infrastructure and services.
- Develop practical troubleshooting and problem-solving skills.

## 3. Complete 100-Day Roadmap

The roadmap is divided into seven major sections.

| Days | Category | Topics |
|---|---|---|
| 1–20 | Linux | Administration and Server Configuration |
| 21–34 | Git | Version Control |
| 35–47 | Docker | Containerization |
| 48–67 | Kubernetes | Container Orchestration |
| 68–81 | Jenkins | CI/CD |
| 82–93 | Ansible | Configuration Management and Automation |
| 94–100 | Terraform & AWS | Infrastructure as Code and Cloud |

### Phase 1: Linux Administration (Days 1–20)

Learn Linux fundamentals, user management, permissions, SSH, security, networking, processes, server configuration and troubleshooting.

### Phase 2: Git and Version Control (Days 21–34)

Learn repository management, branching, merging, remotes, reverting changes, cherry-picking, stashing, rebasing, conflict resolution and Git hooks.

### Phase 3: Docker (Days 35–47)

Learn Docker installation, containers, images, Dockerfiles, networking, port mapping, Docker Compose and application deployment.

### Phase 4: Kubernetes (Days 48–67)

Learn Pods, Deployments, resource limits, rolling updates, rollbacks, volumes, sidecar containers, environment variables, ConfigMaps and Secrets, and application troubleshooting.

### Phase 5: Jenkins and CI/CD (Days 68–81)

Learn Jenkins installation, plugins, user access, jobs, parameterized builds, scheduled jobs, agents, pipelines, deployment jobs and multistage pipelines.

### Phase 6: Ansible Automation (Days 82–93)

Learn inventories, playbooks, modules, package installation, file management, services, ACLs, Jinja2 templates and conditionals.

### Phase 7: Terraform and AWS (Days 94–100)

Learn Infrastructure as Code through Terraform, including VPCs, security groups, EC2, IAM policies, private subnets and CloudWatch alarms.

## 4. Learning Methodology

My learning approach will follow this sequence:

1. **Understand:** Learn the concept before using a command or tool.
2. **Explore:** Understand the purpose and syntax of commands.
3. **Practice:** Perform the assigned practical task.
4. **Troubleshoot:** Investigate errors instead of blindly copying solutions.
5. **Verify:** Confirm that the task has been completed successfully.
6. **Document:** Record the concepts, commands, outputs and lessons learned.

The objective is not just to complete tasks but to understand what is happening behind them.

## 8. Beyond the 100 Days – SRE Learning Path

Completing the initial roadmap will provide a foundation in DevOps tools and infrastructure.

The next learning objective will be to build on these skills and study Site Reliability Engineering (SRE).

The planned SRE topics include:

- Monitoring and Observability
- Prometheus and Grafana
- SLIs, SLOs and SLAs
- Error Budgets
- Logging and Distributed Tracing
- Incident Management
- Root Cause Analysis (RCA)
- Reliability and Performance Engineering
- High Availability and Disaster Recovery
- SRE Automation

This will be a separate learning phase after the initial 100 days.

## 9. Final Goal

The ultimate goal of this journey is to move beyond knowing individual tools and understand how they work together in real-world infrastructure.

I want to develop the ability to deploy applications, automate infrastructure, monitor systems, troubleshoot failures and build reliable services.

**One day at a time. One concept at a time. Practical learning over memorization.**
